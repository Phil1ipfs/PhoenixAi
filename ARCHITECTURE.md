# Architecture

```
React/TS UI --/api (NDJSON stream)--> FastAPI --> ModelProvider (interface) --> OllamaProvider --> Ollama :11434
 (lazy Code/Bench chunks)                |
                                         +--> weather.py (deterministic, no model) --> Open-Meteo geocoding + forecast
                                         +--> research.py (OPTIONAL) --> DuckDuckGo HTML / Wikipedia API / pages
                                         +--> patchgen.py (edit proposals, AST splicing, validation, retries)
                                         +--> SQLite (conversations, messages, settings, projects, patches, benchmarks)
```

## Core
- **Model independence:** `providers/base.py` defines `ModelProvider` (health, list_models, chat_stream, loaded_models, unload). Only `OllamaProvider` knows Ollama. The model id is a runtime setting in SQLite, never hardcoded in logic. Adding another runtime = one new provider class.
- **Memory (data):** SQLite stores model ids as plain strings per message, so changing models never touches stored data. Schema upgrades are additive (`CREATE IF NOT EXISTS`, `ALTER TABLE ADD COLUMN`, new settings get defaults) and tested against a v1 database.
- **Streaming:** `POST /api/conversations/{id}/messages` returns NDJSON events: `start`, `warning`*, `status`*, `sources`?, `token`*, `done` | `error`. Client abort (Stop) cancels the upstream request; the partial reply is saved with `status: stopped`.
- **One generation at a time** (409 otherwise): protects RAM. History is trimmed to `max_prompt_chars`.

## Evidence workflow (internet research, optional, default OFF)
1. `needs_verification(question)` - deterministic regex rules (officeholders, weather, prices, news, recent years, "latest version", weak time words outside code questions). Tested with positive and negative tables.
2. Policy by `web_mode`: `off` (never touch the network; time-sensitive questions get the *unverified* banner + a caution in the system prompt), `auto` (search only when step 1 fires), `always` (search for every message **except** ones `search_skip_reason()` refuses to send to a search engine: passwords/keys/e-mail addresses, code, long private text, greetings; the reason is stored and shown as "Live search skipped: ...").
0. **Follow-ups:** a short continuation ("I mean USA", "until when?", "how about the USA?") is detected/searched together with the last question that was *not* itself a follow-up (`contextual_query`), never as the literal text.
3. `gather_steps()` (async generator; `gather()` wraps it) yields real progress as each step starts: "Searching the web…" -> "Retrieving N sources…" -> "Checking information…"; `main.py` adds "Generating answer…". Steps: cache lookup (in memory, per WebClient; 10 min for weather/prices/news/markets/results, 30 min other time-sensitive, 1 h otherwise; failures never cached; `fresh=true` bypasses; a cached answer keeps the ORIGINAL `retrieved_at` and is labelled "Cached results used ... Search again"), then DuckDuckGo HTML search, Wikipedia API as fallback; top pages are fetched in parallel, boilerplate removed (stdlib `HTMLParser`, infobox rows kept), best-matching blocks selected under a character budget. Each source = `{id, title, url, fetched, retrieved_at, excerpt}`; `fetched=false` means only the search snippet was available and is labelled so. Page reads run in parallel under a time budget (1.5x the web timeout); a slow page keeps its snippet (`fetch_error: deadline`) and cancelled/late fetches are cancelled, never left running. Pages that contain none of the question's key terms are dropped before the model sees them. `published` is taken only from the page's own metadata (meta tags, JSON-LD `datePublished`, `<time datetime>`), else empty.
   **Request log** (`web.search.log`, stored with the reply and shown under "Search details"): one entry per real request: step (cache/search/fetch/filter), original question, actual query, provider, timestamp, status/error, duration, returned URLs, publication date, and after generation `used_in_answer` (was the source cited?).
4. Prompt: numbered sources inside `<<<UNTRUSTED WEB SOURCES ... >>>`; the model is told to answer only from them, cite `[n]`, and say it could not verify otherwise.
5. After generation `verify_citations()`: every `[n]` must be a retrieved source (invalid ones are replaced by "[unverified citation removed]" in the stored/displayed text) and each cited sentence must lexically match its source (numbers must appear in it). Result status: `grounded` / `grounded_weak` / `sources_not_cited`. **This verifies citations, not truth.**
   Then `apply_conflict_guard()`: if two sources report temperatures that cannot both be right (no pair within 3 °C, °F converted), sentences claiming the sources "agree" are removed and a deterministic note listing each source's value is appended (status `sources_conflict`). Leading `[n]` markers after list numbers ("1. [1]") are moved to the end of the line.
6. The UI banner comes from the status (`unverified_disabled|offline|no_results|sources_conflict|weather_*`), not from anything the model says.

## Weather (`weather.py`, deterministic: the model is never called)
Weather is structured data, so it does not go through "search + 3B summary" (which produced one temperature for a whole country and an invented consensus).
1. **Parse** the message with the conversation: place, day (today/tomorrow/day after), hour ("at 4pm"), rain-until questions. Context (pending "which city?", last place + coordinates, asked day, country/region hint) is read from the `weather` metadata PHOENIX stored on its previous reply, so "I mean USA", "How about Los Angeles?", "What about tomorrow?", "until when?" resolve without the model.
2. **Classify before geocoding.** Countries/aliases, US states, Canadian provinces, Australian states, UK nations and continents are recognised by name and answered with a clarifying question (Open-Meteo geocoding returns *Uşak, Türkiye* for "USA", a single point in Kansas for "United States" and a town in Missouri for "California"). A geocoder hit with a country feature code is treated the same way.
3. **Resolve the city:** only populated-place results with valid coordinates; exact-name matches preferred over fuzzy ones; a country/region hint from the pending question filters strictly; "City, State[, Country]" qualifiers filter; several comparable candidates (Springfield) -> PHOENIX lists them and asks; a dominant one (Paris, France vs Paris, Texas) is used and the alternatives are named.
4. **Fetch + validate** current/hourly/daily data for exactly those coordinates. Rejected unless: coordinates in the reply are within 1° of the request, units are °C/km/h/mm, time zone present, every value finite and plausible, arrays consistent. Any failure -> "I couldn't get reliable live weather data ... I won't guess" (status `weather_unavailable`), never a number.
5. **Answer from the numbers**: resolved place label, coordinates, IANA time zone + UTC offset, "Current conditions (observed ...)" vs "Forecast for <date>", °F first for US places (°C in brackets), a note that a city's weather does not describe the country/region the user named, and one citation to Open-Meteo.
With Web Off, clarifying questions still work (no network needed); an actual lookup falls back to the normal cautious path with the "not verified" banner.
- **Web safety:** public http(s) hosts only, standard ports, no credentials in URLs; DNS result checked for private/loopback/link-local ranges on every redirect hop; robots.txt honoured (fail closed on network errors); 600 KB body cap; 3 redirects max; ~1 search/second; plain descriptive User-Agent (+ optional contact for Wikimedia). Failure of any of this degrades to "unverified", never to made-up sources.

## Coding workspace
- **Workspace (`workspace.py`):** every path is relative, resolved (symlinks followed) and confined to the authorized root; secrets/VCS/dependency folders filtered; plain substring search (no regex/ReDoS); `retrieve_context` scores files on demand under a character budget (no persistent index).
- **Patch proposals (`patchgen.py`):** for Python the model returns *complete new definitions* (it is good at that, poor at copying exact text); we splice them in with the AST (replace by name, append new, hoist imports). Other files use SEARCH/REPLACE. Deterministic validation: syntax (`ast`/`json`), no definitions lost, the symbol named in the request actually changed, focused size (<=120 changed lines), diff round-trip. On failure the exact error (plus the closest real line for a missing SEARCH) is sent back, max 2 retries.
- **Patch lifecycle (`patches.py`, `patch_routes.py`):** proposals are stored `pending` with original/proposed text, hashes and validation info. Apply requires explicit approval, checks the file hash (conflict => 409) and writes atomically. Rollback restores the stored original only if the file still matches the applied hash.
- **Benchmark (`benchmark*.py`):** 26 fixed tasks; Python answers run in an AST-allowlisted `python -I` subprocess with a timeout, only after explicit consent. Patch tasks run the same pipeline the product uses; a `strategy` option allows A/B comparison. A test proves every task fails untouched and passes with a reference solution.

## Resource management
- **Pre-flight memory guard** (`sysinfo.assess_memory`): before a reply, free RAM vs. model size (+ context estimate). `warn` shrinks the context to 2048 and shows a notice; `block` (conservative) returns a `low_memory` error without touching the model. Thresholds are heuristics calibrated on this 12 GB machine (see BENCHMARKS.md) and can be disabled/tuned in Settings.
- **`keep_alive`** (passed to Ollama) and an explicit **Unload model now** action release the ~2 GB model on demand. `num_thread` is exposed but left on auto (no reliable benefit measured).
- **UI:** Code and Benchmark views are lazy chunks; health polling pauses while the tab is hidden; no animation libraries.

## Security summary
Localhost bind; requests with a non-localhost `Host` (DNS rebinding) or a foreign `Origin` on state-changing methods (cross-site POST/PUT/DELETE, incl. preflight-free `text/plain` uploads) are rejected by a pure-ASGI middleware; local-only CORS and Ollama URL (parsed, so `127.0.0.1.evil.com` is refused); workspace confinement; secrets blocked; untrusted-data delimiters for files and web pages; no terminal execution; file edits only after explicit approval; benchmark execution needs consent and is restricted (best effort, not a sandbox); the internet is used only when the user enables it, and only for search queries and page requests.
